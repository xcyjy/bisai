# 技术方案与 MVP 实现文档

> 目的：确立实现方向、技术架构、MVP 边界与实现步骤。
> 已定基调：**Python 后端 + Vue 前端**，**MVP = 含在线编辑器的 Web 应用**。
> 剧本类型：**已定为竖屏微短剧（short_drama）**，理由见第二节。

---

## 一、技术选型

| 层 | 选型 | 备选 | 理由 |
|----|------|------|------|
| 前端 | **Vue 3 + Vite** | React | 已定；组件化做"原文/剧本"双栏编辑器 |
| 前端编辑器 | 自研双栏 + YAML 高亮 | Monaco Editor | Monaco 支持 YAML 语法高亮/校验，省事 |
| 后端 | **Python + FastAPI** | Flask | 已定；FastAPI 自带异步、文档、pydantic |
| 数据校验 | **pydantic** | jsonschema | 定义剧本模型，强约束 LLM 输出 |
| YAML 处理 | **PyYAML / ruamel.yaml** | — | ruamel 保留注释，更适合"可编辑" |
| LLM | **Claude（推荐）** | 通义千问/Kimi/DeepSeek | 结构化输出强、长文本一致性好；备选国产模型成本低 |
| LLM 调用 | structured output / tool use | 纯 prompt + JSON 解析 | 强制 schema，减少格式错误 |
| 存储 | 本地文件 / **CloudBase 对象存储** | — | 团队有 CloudBase 经验，可存小说/剧本 |
| 部署 | 本地 demo / CloudBase 云托管 | Docker | demo 跑通即可，部署非重点 |

> ⚠️ **核心工程原则**：LLM **不直接生成 YAML**。流程是 `LLM → JSON（structured output）→ pydantic 校验 → yaml.dump()`。YAML 缩进敏感，直接生成易崩坏。

## 二、剧本类型决策：已定为竖屏微短剧（short_drama）

> **本项目定位：小说 → 竖屏微短剧。** 不做"通用影视 / 短剧双方向"，集中资源把短剧这一条线做深做透。

### 为什么选短剧而不是通用影视

| 维度 | 通用影视剧本 | 竖屏微短剧（✅ 我们的选择） |
|------|------------|--------------------------|
| **差异化/亮点** | 普通，多数队伍都做这个 | **高**，贴合网文 IP 改编短剧的千亿市场，答辩易出彩 |
| **市场契合** | 改编门槛高、周期长 | 正是"小说→短剧"工业化最旺盛的场景，痛点真实 |
| **能力护城河** | 仅做标准转换 | 额外算法化短剧铁律：分集、钩子、扣子、单集时长、产能体检 |
| **对原著要求** | 任意小说皆可 | 适合强情节、强冲突的小说（网文天然契合） |

> 通用影视只是"把小说排版成剧本"，谁都能做；短剧的价值在于**把行业 know-how（2~3 分钟一集、开场钩子、集尾扣子、强冲突快节奏）变成可计算的产线**——这才是评委愿意听的故事，也是我们真正实现了的东西。

### 短剧定位带来的核心能力（均已落地）
1. **场/集分层 Schema**：`scenes` 之上叠加 `episodes` 一等结构（见文档②第 4.9 节）。
2. **自动拆集引擎**（`backend/app/episodes.py`）：按口播时长（≈5 字/秒）贪心打包成集，自动产出 `hook`/`cliffhanger`/`est_seconds`。
3. **短剧产能体检**：对每集做"缺钩子 / 缺扣子 / 时长超标 / 无互动"检查，给出 warnings。
4. **短剧化转换提示词**：`converter.py` 的转换铁律强调快节奏、强冲突、高台词密度。

> ⚠️ 转换阶段（小说→scenes）与编排阶段（scenes→episodes）**解耦**：转换默认即自动拆集，作者也可在编辑器里调整分集边界（改 `scene_numbers`）后重新体检。

## 四、核心 Pipeline（后端最重要的部分）

```
输入：≥3章小说文本
  │
① 分章/分段
  │   按章节标题正则切分（"第X章""Chapter"），保留段落结构
  ▼
② 场景切分 (Scene Segmentation)
  │   LLM 标注每段的 时间/地点/在场人物 → 相邻同时空合并为一"场"
  │   输出：场边界列表
  ▼
③ 全局抽取
  │   扫全文抽 人物表(characters) + 地点表(locations)
  │   作为后续每次 LLM 调用的"参照字典"，保证一致性
  ▼
④ 逐场转换 (核心 Prompt) —— 对每一场单独调用 LLM
  │   规则：心理描写→voiceover；环境→action；对白→dialogue+character
  │   用 structured output / tool use 强制输出固定 JSON 结构
  │   传入：本场原文 + 全局人物表 + Schema 说明 + few-shot 示例
  ▼
⑤ pydantic 校验
  │   JSON → 剧本模型；不合法则带错误信息让 LLM 重试
  ▼
⑥ 一致性检查
  │   人物名校验、空场检测、场号连续性
  ▼
⑦ yaml.dump → 输出 YAML 剧本
```

### Prompt 策略要点（④的关键）
- **角色设定**：「你是专业编剧，正在把小说改编成剧本」。
- **铁律注入**：Show don't tell；心理描写转 voiceover；不臆造原文没有的情节。
- **Few-shot**：给 1–2 个"小说段落→剧本JSON"范例（用文档①那段）。
- **参照字典**：把全局人物表喂进去，要求 character 字段引用表中角色。
- **分而治之**：以"场"为单位调用，避免长文档一次性处理导致遗漏/崩坏。

## 五、MVP 功能边界（做什么 / 不做什么）

### ✅ MVP 必做（保证达标 + 演示效果）
1. 上传 `.txt` 或粘贴**≥3章**小说文本。
2. 一键转换：跑通完整 pipeline，输出结构化剧本。
3. 双栏展示：左原文、右剧本（结构化卡片或 YAML 视图）。
4. **在线编辑**：可改场头、对白、动作、人物（呼应"可编辑"硬指标）。
5. 导出 **YAML 文件**。
6. Schema 校验：保证导出的 YAML 100% 合法。

### 🔶 加分项（时间够再做）
- 原文↔剧本**高亮对照**（点剧本某场，定位原文）。
- 导出 **Fountain / PDF** 标准剧本格式。
- 短剧分集可视化时间轴 / 拖拽调整分集边界。
- 转换质量指标展示（切场数、人物数、对白数、分集体检统计）。
- 闪回/倒叙识别。

### ❌ MVP 不做（明确砍掉，防止超时）
- 用户账户/登录系统。
- 多人实时协作。
- 复杂的多线叙事自动拆解（文档中声明为已知局限）。
- 移动端适配。

## 六、分阶段实现步骤

> 按依赖顺序排，**Schema 契约先行**（前后端都依赖它）。

| 阶段 | 任务 | 产出 | 谁主导(见文档④) |
|------|------|------|------|
| **P0 契约** | 定稿 Schema + pydantic 模型 + 接口约定 | schema.py、API 文档 | 两人一起 |
| **P1 核心链路** | 实现 pipeline ①~⑦，CLI 跑通一篇小说 | 能产出合法 YAML | 后端A |
| **P1 前端骨架** | 搭 Vue 工程、上传页、双栏布局（mock 数据） | 可点击的界面 | 前端B |
| **P2 联调** | 前端接后端 API，真实数据打通 | 端到端可用 | 两人 |
| **P2 编辑器** | 剧本字段可编辑、导出 YAML | 满足"可编辑" | 前端B |
| **P3 打磨** | Prompt 调优、校验完善、UI 美化 | demo 质量 | 两人 |
| **P3 交付** | Schema文档定稿、README、demo视频、仓库公开 | 提交物 | 两人 |

## 七、风险与降级方案

| 风险 | 降级方案 |
|------|---------|
| LLM 输出 JSON 不合法 | structured output 强约束 + 校验失败自动重试 N 次 + 兜底跳过该场并标记 |
| 长小说超时/超 token | 分场调用 + 并发控制 + 进度条；必要时限制章节数 |
| 前后端联调来不及 | 前端先用 mock JSON 开发；后端先用 CLI 验证，最后才接 |
| 切场不准 | 退化为"按章=按场"的保底切分 + 人工可在编辑器调整 |
| 时间不够做编辑器 | 退到文档③策略：先 CLI 产出 YAML，编辑器做只读展示 + 下载 |

> **保命原则**：先保证"小说→合法YAML"这条核心链路跑通（达标线），再加编辑器和加分项。

## 八、答辩亮点清单（提前埋点）

1. **设计原因讲透**：elements 有序列表、voiceover 单列、**场/集分层的 episodes 结构**（见文档②第 4.9 节）。
2. **短剧产线是护城河**：自动拆集 + 钩子/扣子/时长体检，把短剧行业 know-how 算法化。
3. **可量化效果**：展示切场准确率/对白还原率、单集时长分布（哪怕人工抽样）。
4. **贴合真实工作流**：AI 出初稿 + 人在线打磨分集边界。
5. **可扩展性**：Fountain 导出、分集时间轴可视化。
6. **诚实的局限声明**：多线/群戏等边界情况的已知局限——体现专业判断。
